# 3장 - 사용자 식별

### 도입

MySQL → 기존 DBMS와 사용자 식별하는 방식에 차이가 있음

MySQL의 사용자 계정

⇒ 아이디 + 사용자의 접속시점( 클라이언트가 실행된 호스트명이나 도메인이나 IP주소)의 내용을 같이 관리함

MySQL 중요한 특징 = 계정의 권한을 권한세트(Role)로 관리함

그래서 그 권한 세트를 사용자에게 부여시킴

---

3.1 사용자 식별

앞서 말했듯 아이디 + 사용자의 접속시점을 같이 집어넣음

즉, 아이디랑 호스트를 같이 넣어야함

> ‘svc_id’ @ ‘127.0.0.1’

’svc_id’ @ % # 난 공용계정을 만들고 싶어! → % 가 모든 로컬호스트라는 뜻임
> 

만약? 동일한 아이디가 있다면? ⇒ 하나는 공용계정이고 하는 개인계정

그렇다면 mysql이 자체적으로 권한 작은것부터 접근

개인계정에 접근해서 비밀번호 확인함 → 사실 중복 계정 안만들지만

오류 생기면 여기서 많이 생겨서 확인하셈

---

3.2 사용자 계정

Mysql 계정 종류 : 시스템(System Account) 계정 / 일반 계정 (Regular Account)

시스템 계정은 MySQL 내부를 도는 백그라운드 스레드와 무관

시스템 계정도 그냥 사용자를 위한 계정임 (for DBA 관리자)

그럼 일반계정은? → 응용프로그램이나 개발자를 위한 정도

시스템 계정 권한

1. 일반 계정 관리(생성 및 삭제)
2. 다른 세션 또는 그 세션에 실행중인 쿼리 강제종료
3. 스토어드 프로그램 생성할때 DEFINER를 타 사용자로 설정

(DEFINER = view, 함수 등 객체를 생성하는 사람)

그렇다면 3번은 왜 씀? → 권한은 안주고 기능만 쓰게 하기 위해서

---

MySQL 서버에 내장된 계정들이 있음

3개는 필수적으로 필요하니까 지우지 말자

- ‘mysql.sys’ @ ‘localhost’ : sys 스키마의 객체의 DEFINER로 사용되는 계정
- ‘mysql.session’ @ ‘localhost’ : MySQL 플러그인이 서버로 접근할때 쓰는 계정
- ‘mysql.infoschema’ @ ‘localhost’ : information_schema에 정의된 뷰의 DEFINER로 사용되는 계정

---

3.2.2 계정 생성 방법

mysql 5.7까지는 GRANT로 계정 생성 + 권한 부여를 한번에 함

근데 그 이후는 생성은 CREATE USER / 권한 부여 GRANT로 쪼갬

그리고 로그인할때, 옵션 설정 가능 (Ex. 계정의 인증방식, 비번, 비번 관련 옵션 - 유효기간, 재사용불가기간)

## 자주 쓰는 계정 설정 옵션

### IDENTIFED WITH (얘로 구분하겠음)

사용자의 인증방식 + 비번 설정할수 있는데

IDENTIFIED WITH 뒤에는 인증방식(인증 플러그 씀)

기본 인증 방식을 쓰고 싶으면?

> IDENTIFIED WITH BY ‘password’
> 

보통 인증방식은 여기 4개중에 한개임!

- native pluggable authentication (SHA-1)
- cashing SHA-2 pluggable authentication
- PAM pluggable authentication
- LDAP pluggable authentication
